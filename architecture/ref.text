Quick wins (small, high value):

Soft-delete on TerminateProcess — right now it hard-deletes + cascades audit_logs, so terminating a process erases its own replay history. This was flagged and deliberately left as-is during the audit-trail work; it's a small change (use the existing terminated status instead of DELETE) that closes a real gap in the feature we just built.
Multi-token-aware replay — the token-history endpoint flattens all executions of an instance into one timeline. For a process with a parallel gateway or multi-instance task, that means the replay marker jumps between unrelated concurrent branches instead of showing multiple tokens moving at once. Fix: group by executionId, support N simultaneous markers.
Consolidate the 4 duplicate "start process" code paths found this session — they've already caused missed audit instrumentation once; worth merging into one function so it can't happen again.
Medium (real features):
4. A genuine historic archive — separate historic tables populated on complete/terminate, decoupled from live tables. This is the biggest named gap vs Camunda 7's History service.
5. Admin UI in the frontend — Users/Roles have a full API already, no page.
6. Basic analytics (Optimize-lite) — duration distributions, throughput, incident rate — Dashboard.tsx already has some counts to build on.
7. In-browser BPMN Modeler — bpmn-js is already a dependency in view-only mode; swapping to the editable Modeler for authoring+deploy is a moderate lift, not a new library.

Large / architectural (flagging, not committing to):
8. gRPC/Zeebe-native protocol.
9. True partitioned/distributed execution — a different engine, not an incremental change, per the earlier discussion.
